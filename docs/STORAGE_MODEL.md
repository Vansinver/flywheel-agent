# 通用存储层与 Obsidian 可选适配

> **设计提案 / 尚未实现或迁移验证**
>
> 本文区分本机盘点中有文档证据的现状与未来拟议设计。拟议接口、稳定标识、迁移和恢复步骤均未在生产系统或替代平台实现验证。

## 1. 目标与边界

通用存储层负责保存原始收集、整理结果、正式记录、附件引用和运行检查点，并为写入、回读验证和水位推进提供一致约定。它不规定必须使用某一个笔记软件。

Obsidian 可作为一种可选的浏览、编辑和关系图适配层。它可以利用 Vault 目录和 `[[双链]]` 导航笔记，但这不等于 Gate 或存储协议必须调用 Obsidian 应用。

本文是面向公开、可迁移设计的提案，不是生产系统说明或部署指南。相关概览和现有抽象协议见[项目概览](OVERVIEW.md)、[Gate 与双水位说明](NIGHTLY_GATE.md)和[平台兼容性矩阵](PLATFORM_COMPATIBILITY.md)。

## 2. 盘点中有证据的现状

下列事实来自本地流程说明和文件结构的只读盘点；它们描述文档记录的机制，不代表本轮重新验证了生产运行。

- 资料按用途分为原始收集、附件、整理结果、候选观察、正式记录、运行检查点和执行回执等类别。真实资料均属私有边界，不属于本公开草案。
- 文档记录了 Markdown 文件和 JSON 检查点，并使用目录职责与日期命名组织部分输出。模板有嵌入在说明文档中的示例。
- 两个水位分别表示收集已持久化的位置和整理已完成的位置。Gate 读取状态并作决策；它本身不推进水位。
- 收集或整理内容须先写入并回读验证。只有相应阶段验证成功后，才推进该阶段的水位；失败时保留原水位。
- Agent 演化档案使用 Obsidian `[[双链]]` 导航节点，并有关系图入口。这是已观察到的笔记导航约定。
- 本地存在 Obsidian 配置目录；本盘点未读取配置值。没有证据证明特定社区插件、frontmatter 属性或 Obsidian URI 是流程依赖。
- 在已检查的安全说明中，没有发现单独命名的空白模板文件；部分模板以 Markdown 示例形式嵌入说明中。

生产 Gate 的错误处理口径与公开示例存在文档差异：**实际运行时行为尚未核实，需后续核对**。本提案不选择其中一种行为，也不以此推断生产表现。

## 3. 拟议的通用存储约定

以下内容是**拟议设计**，不是现有系统已经具备的接口或 schema。

### 3.1 逻辑资料类别

后端应能区分以下逻辑类别，具体物理目录由适配器配置：

| 类别 | 用途 | 建议的访问特征 |
|---|---|---|
| 原始收集 | 保留来源记录及其顺序，供后续整理 | 追加优先，不静默覆盖 |
| 附件 | 保存原始记录引用的文件 | 通过稳定引用关联，不嵌入公开示例 |
| 整理结果 | 保存按周期组织的摘要或复盘 | 可重建；保留来源引用与验证状态 |
| 候选观察 | 保存仍待验证的模式或假设 | 明确标记候选状态，不自动升级 |
| 正式记录 | 保存经用户确认的原则、阶段或结果 | 受控修改，记录变更来源 |
| 运行状态 | 保存采集与整理检查点及 schema 版本 | 独立持久化，变更需校验 |
| 执行回执 | 记录结果、失败和验证证据 | 追加记录，避免与正式成长内容混写 |

这些类别不要求一一对应到特定文件夹；物理布局应由所选后端提供并记录映射。

### 3.2 后端接口

**拟议设计：** 由一个可替换的存储适配器提供以下操作：

1. 按稳定标识读取来源项目和附件引用。
2. 追加或更新指定类别的记录，并返回写入结果。
3. 回读已写内容，验证标识、版本或内容摘要与预期一致。
4. 读取、校验并更新分开的收集水位和整理水位。
5. 列出记录、附件引用和检查点，以便迁移核对及故障恢复。

实现应明确并发写入、重复请求、原子性和冲突处理策略。仅收到“写入成功”响应，不足以推进检查点；需完成适配器定义的回读验证。

### 3.3 通用稳定标识

**拟议设计：** 每条原始项目使用不依赖笔记标题或物理路径的稳定 ID，并与来源范围及来源提供的记录标识关联。附件使用独立 ID，并由记录引用。ID 生成规则、跨读取视角的稳定性和碰撞处理尚待设计与测试；不得用正文片段或个人账号值构造公开示例 ID。

后端可以把稳定 ID 映射到文件名、Markdown 属性或数据库字段，但映射规则必须可导出、可重建，不能只存在于某个应用的界面状态中。

### 3.4 文件格式与关系

Markdown 和 JSON 是盘点中观察到的文件格式；将它们作为通用后端格式仍属拟议设计。若采用文件后端，建议使用 UTF-8 文本、可配置的相对目录映射，以及机器可校验的检查点 schema。

frontmatter 属性、特定字段名、插件生成的内容和特定 URI 目前**未证实为现有约定**，不应成为通用接口的必需部分。核心关系应先采用稳定 ID 和明确的来源引用；需要 Markdown 链接时，再由适配器生成适合目标工具的链接形式。

### 3.5 水位与验证

**拟议设计沿用已记录的双水位语义：**

- `last_read` 只表示收集结果已写入并回读验证的位置。
- `last_organized` 只表示整理结果已写入并回读验证的位置。
- 两个水位分别提交；一个阶段失败不回滚另一个已经验证成功的阶段。
- Gate 只读取检查点并作出调度决策，不写入、推进或重置水位。
- 数据源报告为空而检查点非空时，停止自动基线处理，交由人工检查。

具体检查点格式、原子更新实现和恢复工具仍需另行设计；本仓库的 Gate 示例只处理输入状态，不实现存储后端。

## 4. 可选的 Obsidian 适配方向

以下是后续可以研究的适配方向，不表示当前已经实现：

- **Vault 映射：** 将通用资料类别映射到可配置的 Vault 子目录。映射表应能导出，不依赖个人 Vault 的绝对路径。
- **双链兼容：** 为稳定 ID 生成 `[[双链]]` 或标准 Markdown 链接，并规定在其他工具中无法解析时的显示与降级行为。
- **图谱呈现：** 从稳定关系生成 Obsidian 图谱视图；图谱属于导航呈现，不作为唯一关系数据库或状态来源。
- **模板与属性：** 先确认实际需要及现有证据，再决定是否使用模板或 frontmatter。当前依赖状态为**未证实**。
- **插件：** 逐项验证插件是否存在、是否为必需以及无插件时的替代路径。当前插件依赖为**未证实**。

不要把整个 `.obsidian` 配置目录直接当作可迁移数据格式；界面布局和本机应用设置应与内容、关系及检查点分开处理。

## 5. 拟议的迁移与恢复步骤

**以下步骤尚未执行或验证：**

1. 从旧后端导出记录、附件清单、稳定 ID、来源引用和检查点快照。
2. 在目标后端建立类别映射与 schema 版本，不覆盖旧数据。
3. 导入到隔离位置，核对记录数、附件引用、ID 唯一性和内容摘要。
4. 验证链接与来源关系；对不支持的链接格式保留稳定 ID，避免静默丢失关系。
5. 只读比较新旧检查点及数据源状态。空源与非空检查点等不一致状态必须交人工处理，不自动重置基线。
6. 在不触发真实采集或正式写入的条件下做演练，确认重复处理、失败恢复和水位推进规则。
7. 用户确认迁移结果后，再切换后端；保留可回滚的旧数据副本和迁移回执。

迁移到新电脑还需要重新配置并授权数据源、调度和运行时环境。换存储工具或新电脑的迁移测试**尚未执行**，不能据此宣称兼容。

## 6. 隐私与实现状态

本文只描述抽象资料类别、通用机制和设计提案，不包含个人笔记、成长记录、真实聊天、附件、运行数据、本机路径、账号或配置值。真实内容、运行状态和授权信息必须留在私有环境。

本文没有实现存储适配器、Vault 映射、链接转换、迁移器或恢复工具。相关能力及替代平台行为均须在明确授权、合成数据和隔离环境中分别验证。
